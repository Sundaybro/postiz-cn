## 修复的重要问题

1. 首次小红书扫码成功后，进度文字污染 JSON，连接仍报失败。项目入口现在只将二维码函数的进度写入 stderr，保留严格的完整 JSON 信封校验。真实入口+离线 QR 替身测试先失败、修复后通过。
2. 意外断电留下磁盘锁，后续无法启动。监督控制改为带 Bearer 密钥的回环端口4319，系统负责独占与退出释放；独立进程 SIGKILL 后同端口重启测试先失败、修复后通过。不按端口强杀其他进程。
3. 小红书源码快照只有 Apache-2.0 元数据，没有完整许可证文本；本分发补入 Apache 官方标准文本，保留来源说明。

修复后的全套相关测试：30 项桥接/运行控制测试、3 项表单测试通过。番茄 MCP 协议工具列表离线检查通过。前后端生产构建及本机启动/停止/重启已经验证。未做第二轮重复审查。

- 番茄账号绑定昵称+可读作品ID集合，因为连接器没有稳定作者ID；集合变化需重新连接。代价是新增作品可能要求重连。
- 番茄审核结果由本人在作者后台核查，提交不等于审核通过。代价是自动审核状态同步尚未提供。
- 真实扫码、上传、发布和审核未验收；离线与协议检查不能保证平台当前可用。
- 连接器中其他短故事、微头条、互动功能不暴露给桥接，不在本次验收范围。
- 一键原生安装仅验收 macOS Apple Silicon；Linux/Intel安装需后续适配。
- 当前交付是本机开发预览，不是公网生产部署；没有创建或推送公开仓库。
- 控制从私有Unix socket改为回环端口，换取系统级自动释放；代价是额外占用4319端口。密钥和Origin校验仍保留，其他项目占用时拒绝接管。
