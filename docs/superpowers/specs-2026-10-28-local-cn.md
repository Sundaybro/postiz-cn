# Postiz 中文本机版：首版设计

状态：待用户确认完整设计。已确认本机单用户、小红书和番茄小说；下述具体实现与边界为开发者建议。

## 目标

基于 gitroomhq/postiz-app 实际源码二次开发，在本机浏览器中管理小红书图文笔记和番茄小说章节。复用 Postiz 草稿、素材、日历、任务编排，不把现有 Boom Agent 前端换皮冒充 Postiz。

首版给用户本人使用，不开放公网注册、不提供多人 SaaS、不接支付。不把开发授权当成真实内容发布授权；开发验证默认离线，真实发布需用户指定内容并在界面确认。

## 已知环境与依据

- 当前 boom-agent 根目录没有 Git 元数据；现有 frontend 是 Vite + TypeScript，backend 是 FastAPI，并不是 Postiz。
- tools/xiaohongshu-cli 已存在，README 声明支持 JSON 信封、图文发布、离线 dry-run、原生定时和扫码登录。真实效果仍需验证。
- tools/fanqie-autopub-mcp 已存在，MIT，支持作品/章节列表、章节发布、原生定时、登录、MCP stdio；不得修改或提交 data 中的凭证。
- 已读取上游 SocialProvider 接口：支持自定义渠道、认证、发布、发布结果、待确认状态及状态轮询。
- 本机已有 Node v25.8.2、pnpm 命令入口、Chrome；PATH 未找到 docker，应用目录也未发现 Docker 应用。不能假定已有可运行的容器环境。
- 上游源码：https://github.com/gitroomhq/postiz-app 。正式实施必须记录拉取的提交号，并按该版本实际结构细化变更。

## 方案选择（开发者建议）

采用 Postiz 源码 fork + 本机渠道桥接服务。另建 postiz-cn/ 独立 Git 仓库，保留 upstream、AGPL 与原始版权；既有工具目录保持独立，通过配置引用。

相比从零写后台，这条路径复用现有产品；相比把浏览器和 Python 全塞入 Postiz 容器，桥接方式便于复用宿主机 Chrome、扫码窗口和登录态。

Postiz 的数据库、Redis、Temporal 优先通过 Docker Compose 运行；开发态前后端按上游要求运行。先检查 Node/pnpm 版本约束与容器可用性；缺少依赖时按真实环境补齐，不在现有 Node 上盲装。安装系统级容器运行环境必须走工具权限授权。

宿主机桥接服务用 Node + TypeScript，调用小红书 CLI 和番茄 MCP；Postiz 通过受认证接口调用它。桥接代码纳入新项目源码。若容器调用宿主机，必须验证实际网络路径并在所有接口上校验随机密钥；不默认把免鉴权 MCP 暴露到非回环地址。

## 用户路径

1. 启动本机服务，浏览器打开本地 Postiz。
2. 创建一个本地管理员账号，无需官方 Postiz 账号、邮件服务或订阅；之后关闭新增注册。保留原登录机制。
3. 在账号页选择小红书或番茄，打开扫码/登录窗口。显示未连接、待扫码、已连接、登录失效、环境未就绪；未实际校验前不能显示已连接。
4. 选择渠道，创建内容，保存草稿，预览后确认立即发布或排期。
5. 从日历和任务页查看处理结果。平台接受、审核中、已发布、失败、结果待核查分别展示。

## 小红书范围

- 首版支持一个连接账号的图文笔记；使用标题、正文、多图、话题和 AI 声明字段。不做视频、评论、私信或批量互动。
- 图片上传到本地存储；桥接服务只接受受管素材标识并解析到允许目录，不提供任意文件读取接口。
- 本地预览使用离线校验；不能上传素材、创建线上草稿或发布。
- 使用 CLI 参数数组调用进程，不拼 shell 命令。解析 ok/data/error 信封，并保留必要的错误码。
- 小红书原生定时是否使用取决于当前 CLI 能力与返回结果。首版统一由 Postiz 在到期时发起即时发布，避免两层定时重复执行；界面明确本机需开机且服务在运行。
- 登录凭证由现有 CLI 管理，Postiz 仅保存连接引用和可展示的账号信息，不保存或返回原始 Cookie。

## 番茄小说范围

- 首版连接一个作者账号，读取已有长篇作品和章节；不自动新建小说、修改线上旧章节或删除内容。
- 专用表单包括书籍、章节序号、章节标题、正文、字数和 AI 使用声明。作品及章节 ID 全程使用字符串。
- 支持输入正文或导入 UTF-8 TXT；首版一次提交一个章节，批量导入发布、短故事、微头条放到后续。
- 小说章节保持为独立发布内容，不将多个章节映射为社交平台的评论线程。
- 通过 MCP SDK 调用现有 stdio 服务；复用进程、串行操作浏览器，解析 MCP isError 和业务结果。
- 预览只在新后台本地完成。现有 add_chapter_tomato 的 confirm=false 可能填表并触发自动保存，不能作为无副作用预览使用。
- 实际提交只在用户确认后调用 confirm=true。AI 声明由用户明确选择，桥接层显式传值，不依赖工具默认值。
- 排期同样由 Postiz 到期调用即时发布；遇到验证码、实名或人工验证时暂停并提示用户处理。

## 通用行为与数据

- 默认时区 Asia/Shanghai，数据库保存 UTC；编辑表单显示明确时区。
- 草稿保存内容类型、目标账号、渠道参数和版本；确认发布绑定当前版本和内容摘要。编辑内容会使之前的发布确认失效。
- 采用 Postiz 原有持久化队列与任务 ID；桥接任务记录 taskId、内容摘要、目标、执行阶段、远端 ID、时间和脱敏错误。
- 发布阶段：草稿 → 待执行 → 执行中 → 已提交/审核中 → 已发布；另有失败、需登录、结果待核查。UI 显示中文且映射到上游内部状态，不能随意破坏原有状态机。
- 任务必须防重复提交；相同任务 ID 不得重复发布。写入开始前记账，完成后保存远端 ID；不确定结果先只读核查，不能因 Temporal 重试再次盲发。
- 同账号并发发布串行化。发布成功以远端结果为准，进程退出码、页面点击成功、排队成功均不等于已发布。
- 重启后恢复未执行任务；执行中但未确认结果的任务进入待核查。错过时间的任务保留并提示用户选择立即执行或改期，不在重启时集中补发。
- 休眠/关机无法保证准点执行，界面排期说明与 README 明示。本机原生定时能力后续可独立增强。

## 本地边界与运维

- 对外网页和基础设施端口尽量仅绑定回环地址；容器内部按必要范围通信。桥接接口采用随机密钥、请求体校验、超时和明确的 Origin/CSRF 策略。
- 不提供任意命令执行、任意路径、任意 MCP 工具名透传；桥接端点仅实现已批准的渠道功能。
- 日志不记录 Cookie、令牌或完整发布正文；截图和原始错误放本地私有目录，展示前脱敏。
- 本地数据库、媒体、桥接任务记录有持久卷或明确目录，提供备份和停止说明；凭证与个人内容不进入 Git。
- AGPL 许可、版权、变更说明和对应源码入口保留；不沿用 Postiz 官方服务身份。
- 首版不承诺全站中文，优先翻译注册/登录、账号连接、编辑器、日历和任务结果等主要使用路径。

## 验收

1. 全新环境按 README 启动，完成本地注册后关闭新增注册，重启数据不丢失。
2. 两种账号均能展示真实连接状态，失效时不能误报可发布；不在前端暴露凭证。
3. 两种内容可新建、保存、重开、编辑、预览和排期；预览验证平台端无写入。
4. 自动化测试覆盖参数映射、错误解析、连接失效、跨时区、重复提交、提交后超时、进程重启恢复和同账号并发。
5. 离线桥接替身验证完整 UI 与任务流程；离线成功不能标注真实平台发布通过。
6. 真正发布验证分别由用户提供内容，在界面明确确认后执行并读取远端结果；未获授权时仅报告未实测项。

## 后续实施顺序

先固定上游版本并跑通原始本机实例，再实现桥接契约与离线测试，再添加两个渠道与中文表单，最后验证日历、重试、连接、启动文档及真实发布。不能用静态演示页面替代真实 Postiz 接入。
